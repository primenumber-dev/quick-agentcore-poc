## 1. 応答時間の改善検証

これまでの検証で、現行のホスティング方式(AgentCore Runtime)は、1回の呼び出しに約6秒かかることが分かっていた。今回、「同じ利用者からの連続した呼び出しであれば、サーバー側の実行環境を使い回すことで高速化できるのではないか」という仮説を実際に検証した。

結果、直前の呼び出しから30秒以内であれば、応答時間は約6秒から約0.5〜0.6秒まで短縮されることを確認した(約10倍の改善)。ただし、5分以上間隔が空くと、この改善効果は失われ、通常の約6秒に戻ることも確認した。

この結果が意味するのは、AIアシスタントが立て続けに複数の操作を行うような使い方では大きな体感速度の改善が見込める一方、「久しぶりに使う」「1回だけ利用する」といった使い方では、今回の対策の恩恵を受けにくいという点である。実際の業務での利用パターンに応じて、体感速度がどう変わるかを見極める必要がある。

## 2. 外販に向けたセキュリティ機能の課題整理

金融機関向けにサービスを外販する場合に必要となる、利用者管理(DCR)と通信保護(WAF)の機能について、実際に動かして検証した。

### 利用者管理(DCR)の一連の流れ

新規の利用者が自分で接続情報を発行し、それだけでは即座に利用できず、サービス提供者側の承認作業を経て初めて利用可能になる、という一連の流れを実際に動かして確認した。また、不正利用が判明した際に、該当の利用者のアクセスを即座に遮断できることも確認した。

さらに今回、この仕組みをより低コストに実現できる可能性のある2つの代替方式を新たに発見した。いずれも、現在の実装で使っている追加のプログラム(Lambda関数)を減らせる可能性があり、今後の実装方針の選択肢として検討していく。

### 通信保護(WAF)

不正な攻撃パターンを検知して遮断する仕組み(WAF)が実際に機能していることを再確認した一方、現在設定されている防御ルールでは、SQLインジェクション攻撃に特化した検知ルールが含まれていないことを新たに発見した。金融機関向けサービスとして防御機能を訴求する場合、この追加対応が必要になる。

## 3. 最新プロトコルへの対応検証

AIアシスタントとの接続に使う通信規格(MCP)には最新版が存在し、今後主流になっていくと見込まれる。今回、試験的に最新版に対応する実装を作成し、現行の実装から機能を損なうことなく切り替えられることを確認した。

現時点ではこの実装は試験段階に留めており、実際のサービスへの反映は行っていない。今後、正式に移行するかどうかは別途判断する。
